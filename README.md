# 世界遺産検定2級 一問一答

世界遺産検定2級の対策用に作った、4択の一問一答クイズです。ブラウザで `index.html` を開くだけで動きます（ビルド・サーバー不要）。

## 特徴

- **全150問**、5カテゴリ（条約と理念／しくみと制度／危機遺産と保護／日本の遺産／世界の遺産）
- **3段階の難易度**（簡単・普通・難しい）から選んで出題できる
- **4つの選択肢すべてに解説つき**。正解の根拠だけでなく、選ばなかった誤答が「なぜ誤りか」まで表示されます
- 多くの問題に**補足**（関連する年号・件数・類似事例）を付与
- カテゴリ絞り込み／出題数（10・20・30・50・すべて）／ランダム出題・収録順の切り替え
- 進捗バー、カテゴリ別＋難易度別の正答率、まちがえた問題の一覧と復習モード
- **選択肢の並び順は毎回シャッフル**。正解の位置を覚えてしまうのを防ぐ
- 正誤は色だけでなく**記号（○ / ✕ / –）と文字**でも示すので、色の見分けに頼らない
- **マスコットが褒めたり励ましたりする**。正解・誤答・連続正解・結果で表情と台詞が変わる
- マスコットは3体。**20回に1回で白いほう、100回に1回で灰色のほう**が出る（台詞もそれぞれ専用のものに変わる）
- スマートフォンでの表示に対応（タップ領域はおよそ44px以上、1カラムに積む）
- キーボード操作：`1`〜`4` で回答、`Enter` / `Space` で次の問題へ
- ライト／ダークテーマ対応、スマートフォン幅対応
- 直近の成績は端末の localStorage にのみ保存されます（外部送信なし）

## 難易度

| 難易度 | 対象 | ねらい | 問題数 |
| --- | --- | --- | --- |
| 簡単 | `level === 1` | 基本用語と代表的な遺産 | 48問 |
| 普通 | `level === 2` | 登録の経緯や基準の中身 | 53問 |
| 難しい | `level === 3` | 年号・件数・勧告の経緯などの細部 | 49問 |

カテゴリ×難易度のどの組み合わせでも出題できるよう、**5カテゴリそれぞれに3段階すべてを6問以上置いてある**。
問題を足すときもこのバランスを崩さないこと。ある組み合わせが0問になると、その範囲を選んだ人は
「はじめる」が押せなくなる。

| カテゴリ | 簡単 | 普通 | 難しい | 計 |
| --- | ---: | ---: | ---: | ---: |
| 条約と理念 | 8 | 9 | 8 | 25 |
| しくみと制度 | 10 | 12 | 12 | 34 |
| 危機遺産と保護 | 6 | 7 | 7 | 20 |
| 日本の遺産 | 15 | 16 | 14 | 45 |
| 世界の遺産 | 9 | 9 | 8 | 26 |

## 使い方

```
git clone https://github.com/roomhair/worldheritage-quiz
cd worldheritage-quiz
open index.html          # macOS。Windows は start index.html
```

配布・共有には `dist/worldheritage-quiz.html` を使う。CSS と JS を埋め込んだ1ファイル版で、
ダブルクリックするだけで動く。`data/questions.js` などを編集したら作り直すこと:

```
node build-standalone.js
```

## デザインの決めごと

`styles.css` を触るときの前提。

- **箱で囲わず、髪罫と余白で区切る**。角丸カードを積み重ねない。登録台帳のような、罫線主体の構成
- **色は緑青 `--accent` ひとつ**。正解表示もこれを使い、色数を増やさない。弁柄 `--wrong` は誤答にだけ使う
- **難易度は色ではなく本数**（3本ゲージ）で示す。色覚に依存させない
- 書体は **IBM Plex Sans JP + IBM Plex Mono** の同一スーパーファミリー。数値・ラベルはモノスペースの等幅数字で桁を揃える
- 和文の可読性に合わせ、本文は `line-height: 1.85` / `letter-spacing: .02em`、本文幅は1行40字前後（`max-width: 45rem`）
- 色は必ずトークン経由で書く。`:root` に明のパレットを全部定義し、`prefers-color-scheme` と `[data-theme]` では**トークンだけ**を上書きする。メディアクエリの中だけで定義された色があると、OSの設定によっては読めない配色になる
- 単一選択のチップ（難易度・出題数・出題順）はベタ塗り、複数選択のチップ（カテゴリ）は淡く。既定で全部ONのカテゴリがベタ塗りだと面が重くなるため
- **`<meta name="viewport">` は消さないこと**。これがないとスマートフォンが幅980pxとみなしてページ全体を縮小表示する。`<meta charset="utf-8">` も同様で、`dist/` の1ファイル版をローカルで開いたときの文字化けを防ぐ

## マスコット

3体いる。`app.js` の `mascotSVG(mood, who)` がSVGを組み立て、毛並みは `index.html` の
`#fur` フィルタ（`feTurbulence` + `feDisplacementMap`）で出している。画像ファイルは使っていない。

| who | 見た目 | 出現率 | 台詞 | 吹き出しの縁 |
| --- | --- | ---: | --- | --- |
| `sun` | 青いモコモコ。大きな目、黒い腕 | 94% | `LINES` | 緑青 |
| `non` | 白いモコモコ。ぼんぼり、豆粒の目、赤い鼻と腕。口なし | **5%** | `NON_LINES` | 赤 |
| `gent` | 灰色のふさふさ。シルクハット、黒い長い手足、とじた波形の目 | **1%** | `GENT_LINES` | 焦茶 |

出現率は `RARE` の確率表で決まる。珍しい順に判定し、どれにも当たらなければ `sun`。
率を変えたいときはこの表の `p` だけを直せばよい。

```js
var RARE = [
  { who: "gent", p: 1 / 100 },
  { who: "non",  p: 1 / 20  }
];
```

`toon()` が表示のたびに `rollWho()` を呼ぶので、**あいさつ・回答直後・結果**のどこでも入れ替わる。
珍しい2体は小さく弾んで現れる（`gent` のほうがゆっくり）。

気分は `data-mood` 属性で切り替え、見た目はすべてCSS側で定義している。表情の作り方は体ごとに違う。

- `sun` — 目玉の位置、口の形（`.mouth-*` を出し分け）、腕の角度
- `non` — 目が豆粒で口もないので、**腕の角度と目の形**（にっこりすると弧になる）だけ
- `gent` — **腕の角度と帽子の浮き沈み**。目はとじたままで動かさない

腕は肩を軸に回すので、**左腕は正の回転で上がる**（右腕は負）。符号を逆にすると体の前で腕を組んだ形になる。
`gent` は手が別パーツなので腕と同じグループ（`.limb`）に入れてある。分けると腕を上げたとき手が置き去りになる。

| mood | 出る場面 |
| --- | --- |
| `idle` | 設定画面（前回の記録があるとき） |
| `cheerup` | 設定画面（初回）、正答率60%未満の結果 |
| `good` | 正解、正答率75%以上の結果 |
| `oops` | 誤答 |
| `party` | 3問以上の連続正解、正答率90%以上の結果 |
| `think` | 予備（現在は未使用） |

台詞は配列で持たせ、`pick()` が直前と同じものを避けて選ぶ。候補から除いて選ぶ方式にしてあり、
引き直し方式には戻さないこと（乱数が偏るとループから抜けられなくなる）。

差し替えたい場合は `sunSVG()` / `nonSVG()` / `gentSVG()` の戻り値と `.mascot[data-who=...]` のCSSだけを
直せばよく、呼び出し側（`toon()`）は触らなくてよい。4体目を足すときは、SVGを返す関数・`RARE` の1行・
台詞の定数・`toon()` 内の対応表の4か所。

## 設問を追加・編集する

`data/questions.js` の配列に、次の形式でオブジェクトを追加します。

```js
{
  id: 151,                   // 一意の番号
  cat: "日本の遺産",          // 既存カテゴリ名にすると自動でチップに集計される
  level: 2,                  // 1=簡単 / 2=普通 / 3=難しい
  q:  "問題文",
  a:  2,                     // 正解の choices インデックス（0起点）
  choices: [
    { t: "選択肢1", e: "この選択肢が誤り（または正解）である理由の解説" },
    { t: "選択肢2", e: "..." },
    { t: "選択肢3", e: "..." },
    { t: "選択肢4", e: "..." }
  ],
  note: "補足（任意）"
}
```

新しい `cat` を書けば、カテゴリのチップは自動的に増えます。

## 公開（GitHub Pages）

`.github/workflows/pages.yml` がリポジトリの中身をそのまま GitHub Pages にデプロイする。
公開URLは:

```
https://roomhair.github.io/worldheritage-quiz/
```

公開するには、先に **Settings → Pages → Build and deployment → Source** を
**GitHub Actions** にしておく必要がある（リポジトリはすでに public）。

ワークフローは `build`（全ブランチ）と `deploy`（`main` のみ）に分かれている。
Pages 環境は既定でデフォルトブランチからのデプロイしか許可しないため、
実際に公開するには変更を `main` にマージする。

`build` ジョブは次の3つを行う。

1. **設問データの検証** — id の重複、選択肢がちょうど4つあるか、
   **4つすべてに解説 `e` があるか**、`a` が 0〜3 の整数か、`level` が 1〜3 か、
   **カテゴリ×難易度の組み合わせに空がないか**。
   解説の付け忘れも、難易度の偏りもここで落ちる。
2. **1ファイル版の同期確認** — `dist/worldheritage-quiz.html` がソースから作り直された
   状態か。`data/questions.js` などを編集したら `node build-standalone.js` を実行して
   コミットすること。
3. **キャッシュ対策** — 配信するHTMLの `styles.css` / `app.js` / `data/questions.js` の
   参照にコミットSHAを付ける（`data/questions.js?v=559c1231` のように）。ブラウザが
   古い css/js を掴んだまま新しいHTMLと混ざるのを防ぐためで、**リポジトリのファイルは
   相対パスのまま**なので `index.html` を直接開く使い方は変わらない。
   フッターにそのSHAを出しているので、表示中のページがどのビルドか判別できる。

## 注意

出題内容は公式教材の範囲を踏まえた**学習用の自作問題**であり、実際の検定問題ではありません。難易度の3段階も、公式の区分ではなく本アプリ独自の目安です。制度や登録件数は 2024年の登録（日本26件：文化21・自然5）時点の情報にもとづいています。
